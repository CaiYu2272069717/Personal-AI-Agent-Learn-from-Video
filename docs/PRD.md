## 1. 背景与目标

### 1.1 背景

短视频平台（抖音、哔哩哔哩）上有大量有价值的知识类内容，但视频形式不利于回顾、检索和沉淀。手动记笔记效率低，看过即忘。公众号/网页文章类内容也有同样的"看完就丢"问题。

### 1.2 产品目标

分两层：

1. **知识提取层**：粘贴一条分享链接 → 自动完成"下载 → 音频提取 → 转录 → AI 总结" → 生成结构化学习文档 → 入库可检索。
2. **智能体层**：把库中沉淀的知识作为个人知识库（RAG），提供一个**全功能专属 AI Agent**——能围绕知识库问答对话；能**联网**检索资料；也能像通用助手一样帮忙干活（执行命令、处理文件、调用系统内的下载/转录/OCR 等工具）。

一句话：**把碎片化的视频/文章变成个人知识库，再让一个懂我知识库的 Agent 替我干活。**

### 1.3 成功标准（个人版）

- 全自动模式：粘贴链接后无人工干预，端到端产出学习文档；10 分钟内视频全流程 ≤ 3 分钟
- 半自动模式：流水线任意阶段可单独使用（如"只下载视频""只转录音频文件"）
- 成本可控：ASR/LLM/Embedding 均为可换的 OpenAI 兼容接口，单条视频成本 < 0.1 元
- Agent 问答能引用知识库中的具体条目作答；执行命令/写文件前有确认机制，不出安全事故

## 3. 双工作模式（核心交互设计）

流水线阶段定义：

```
[S1 解析链接] → [S2 下载视频] → [S3 提取音频] → [S4 分割音频] → [S5 ASR 转录] → [S6 LLM 总结] → [S7 入库]
```

### 3.1 全自动模式（默认）

- 输入链接 → S1→S7 一路跑完，无需干预。
- 结束后**弹窗询问是否保留原视频文件**，默认删除（提供"记住我的选择，不再询问"选项）。
- B 站多 P/合集：提交后**弹窗询问处理全集还是单 P，默认单 P**；选全集则每 P 生成独立条目并排队。

### 3.2 半自动模式（阶段自由组合）

- **任意入口**：分享链接 / 本地视频文件 / 本地音频文件 / 纯文本（转录稿或文章）——从对应阶段进入流水线。
- **任意出口**：提交时选择"执行到哪一步为止"，中间产物直接交付给用户。
- 由此天然派生出一组独立小工具（同一套底层能力，不需要单独开发）：

| 派生小工具 | 入口 → 出口 | 产出 |
|------------|-------------|------|
| 无水印视频下载器 | 链接 → S2 | 视频文件 |
| 音频提取器 | 链接/视频文件 → S3 | mp3 音频 |
| 音频切割器 | 音频文件 → S4 | 分段音频 |
| 音频/视频转录器 | 链接/视频/音频 → S5 | 转录文本 |
| 文本总结器 | 文本 → S6 | 学习文档（可选不入库） |

- 半自动模式下不涉及"是否保留视频"问题——产物即交付物，由用户自行处置。
- 任意半自动产物可随时"继续下一阶段"（断点数据都在 `workdir/{id}/`，见 F7）。

### 4.2 功能详细说明

#### F1 链接解析

- 正则提取 URL；按域名路由：`douyin.com / iesdouyin.com` → 抖音；`bilibili.com / b23.tv` → B 站；其他 → 文章。
- 抖音：复用 temp 中 `DouyinProcessor.parse_share_url`（`window._ROUTER_DATA` 解析，`playwm→play` 无水印直链），支持 video 与 note（图集）两种页面；图集走 F-OCR 分支。
- B 站：yt-dlp 解析；检测到多 P/合集时返回分 P 列表，前端弹窗让用户选择（默认单 P，即当前 P）。
- 文章：trafilatura 抽取正文转 Markdown。
- 异常（链接失效、需登录、地区限制）→ 明确报错。

#### F3 音频处理

- ffmpeg 提取，统一转 16kHz 单声道 mp3。
- 分割阈值可配：默认文件 > 45MB 或时长 > 55 分钟触发，9 分钟/段（复用 temp 成熟策略）。

#### F4 转录（ASR）

- 协议：OpenAI 兼容 `POST {base_url}/audio/transcriptions`。
- 默认硅基流动 `FunAudioLLM/SenseVoiceSmall`；`asr.base_url / api_key / model` 全部可在设置页修改，**换供应商零代码改动**（前提是 OpenAI 兼容）。
- 分段并发转录（默认 2），转录时传视频标题作 context 提升专有名词准确率。

#### F5 总结整理

- 输出文档骨架：一句话总结 / 核心要点 / 详细笔记 / 金句摘录 / 行动清单 / 原始转录（折叠）。
- Prompt 模板存 `prompts/*.md` 可编辑。
- **LLM 配置独立于 ASR**：`llm.base_url / api_key / model / temperature`。前期可与 ASR 同用硅基流动，余额用完直接在设置页切换 DeepSeek 或其他家。
- 超长转录 map-reduce 分块总结。

#### F-OCR 图文识别

- 场景 A：抖音图集/文章内嵌图片 → 逐图 OCR → 合并文本 → 进入总结流程。
- 场景 B：作为 Agent 注册工具 `ocr_image(path_or_url)`——当 Agent 配置的 LLM 不支持视觉输入时，Agent 用它来"看图"。
- 后端两种实现可配：① 视觉 LLM API（OpenAI 兼容 VLM，如硅基流动的 Qwen-VL 系）；② 本地 PaddleOCR（离线免费，P2）。默认走视觉 LLM。

#### F6 知识库

- SQLite 单文件 + `library/` Markdown 镜像（普通文件夹即可，不要求 Obsidian；将来想用 Obsidian 直接把 vault 指向该目录）。
- 去重：同 `source_id` 重复提交时提示，可覆盖或跳过。

**数据模型（核心表）**：

```sql
items(
  id INTEGER PK,
  source TEXT,            -- douyin / bilibili / article / local
  source_id TEXT UNIQUE,
  url TEXT, title TEXT, author TEXT,
  duration_sec INTEGER,
  status TEXT, error TEXT,
  transcript TEXT, summary_md TEXT,
  tags TEXT, md_path TEXT,
  created_at, updated_at
)
items_fts (FTS5: title, transcript, summary_md, tags)

-- v0.2 新增：向量分块（RAG）
chunks(
  id INTEGER PK,
  item_id INTEGER FK,
  chunk_index INTEGER,
  text TEXT,
  embedding BLOB          -- sqlite-vec 存储
)

-- v0.2 新增：Agent 会话
conversations(id, title, created_at)
messages(id, conversation_id FK, role, content, tool_calls_json, created_at)
```

#### F7 任务管理

- 流水线阶段（S1–S7）解耦为独立步骤函数，任务 = {入口阶段, 出口阶段, 输入}；全自动即 S1→S7 的特例。
- 单机 asyncio 队列；每阶段产物落盘 `workdir/{id}/`（video.mp4 / audio.mp3 / segments/ / transcript.txt / summary.md）。
- 断点续跑：检测已有产物跳过对应阶段；半自动产物"继续下一阶段"同机制。
- 全自动完成后触发"是否保留视频"弹窗（默认删除，可记住选择）。

#### F8 WebUI

页面结构（FastAPI + Jinja2，轻量无前端框架，进度用 SSE）：

1. **提交页**：粘贴链接/选本地文件 + 模式选择（全自动/半自动出口阶段）+ 模板选择；任务进度实时展示；交互弹窗（多 P、保留视频）。
2. **知识库页**：卡片列表、关键词/语义搜索、详情查看（渲染 Markdown）、重新总结、删除。
3. **对话页（Agent）**：聊天界面，展示工具调用过程与引用来源；危险操作确认弹窗。
4. **设置页**：四组独立 API 配置（ASR / 总结 LLM / Agent LLM / 嵌入模型，各自 base_url+key+model）+ OCR 后端 + 清理策略 + 分割阈值。Key 存本地配置文件，不入库不打日志。

#### F9 AI Agent（v0.3 升级为"全功能专属智能体"，本系统第二支柱）

> 设计基调：Agent 不是"轻量问答机器人"，而是一个**能干活的通用助手**——读得懂你的知识库、上得了网、动得了文件、跑得了命令，但要可管可控、可回退。

**a) 知识库 RAG 问答**
- 入库时自动分块（标题层级+定长混合，约 500 token/块）→ 调嵌入 API → 存 `chunks` 表（sqlite-vec）。
- 嵌入模型默认硅基流动 `BAAI/bge-m3`（OpenAI 兼容 `/embeddings` 接口，可换）。
- 问答：向量检索 top-k + FTS5 关键词召回混合 → 拼入上下文 → Agent LLM 回答，**必须标注引用条目**（标题+链接）。
- 答非所问兜底：检索不到相关内容时，明确说"知识库里没有相关内容"，**不编造**；必要时建议走联网工具补查。
- 已有库存内容：提供"一键补建索引"按钮批量嵌入。

**b) 联网能力**
- `web_search(query)`：调用联网搜索（默认 **Tavily**，用户已提供 key；Querit 作备选，设置页可切换）返回结果列表（标题+URL+摘要）。
- `web_fetch(url)`：抓取网页正文转 Markdown 喂给模型，回答时**标注来源 URL**。
- 用途：补全知识库没有的时效性信息、查证事实、读在线文档。联网工具返回同样作为上下文，模型作答须标明来源。

**c) Agent 工具集（function calling，全功能）**

| 工具 | 说明 | 风险级别 |
|------|------|---------|
| `search_knowledge` | 检索知识库（向量+关键词） | 安全 |
| `get_item` | 读取某条目完整内容 | 安全 |
| `run_pipeline` | 调用本系统流水线（下载/转录/总结一条新链接） | 安全 |
| `ocr_image` | 图片文字识别（视觉兜底） | 安全 |
| `web_search` | 联网搜索 | 安全 |
| `web_fetch` | 抓取网页正文 | 安全 |
| `read_file` | 读本地文件 | 低危 |
| `list_dir` / `glob_files` | 列目录 / 按模式搜文件 | 低危 |
| `edit_file` | 精确替换文件片段 | 中危，需确认 |
| `write_file` | 写/创建文件 | 中危，需确认 |
| `run_command` | 执行 shell 命令（支持长时任务） | 高危，需确认 |

> 工具集后续可按需扩充（计算器、日历、定时任务、外部 MCP 等），框架保持开放。

**d) 三级权限模型（可管可控，不强硬）**

| 权限档 | 触发条件 | 行为 |
|--------|---------|------|
| **默认（批准制）** | 初始默认 | 安全级工具直接执行；中/高危工具（`edit_file`/`write_file`/`run_command`）执行前弹**确认卡片**（展示完整命令/路径/内容），用户批准才执行 |
| **完全访问** | 设置页开启开关 | 所有工具免逐次确认直接执行；审计日志照常记录；仅"不可逆系统级破坏"类命令（见黑名单）仍拦截 |
| （可选）**严格/只读** | 暂未默认提供 | 如需可加：禁止一切写/执行 |

- **命令黑名单（永远兜底，不可被完全访问绕过）**：`rm -rf /`、磁盘/分区格式化、修改系统注册表、删除系统目录等真正不可逆的系统级破坏。名单在设置页可查看，且**按用户意愿放行**（个人自用，尊重用户意志）。
- **文件操作边界（优先级制，不硬锁）**：默认边界 = 项目 `workspace/` 子目录；Agent 操作越界路径（如到 D 盘某项目）时，不强行拒绝，而是**升级询问**"是否允许访问 X 目录？"，用户确认一次后可记住该目录为可信边界。兼顾安全与"可能来错文件夹"的灵活需求。

**e) 全局记忆（让 Agent 越用越懂你）**
- Agent 每次对话开头注入 `workspace/agent_memory.md`，分两个区：
  - **固定区（FIXED）**：Agent 人设说明、协作基本风格、以及"修改本记忆的规则"（如：你只能编辑可变区，不得修改固定区；调整人设由用户完成）。**模型被硬性约束不得自改固定区**；用户可随时手动修改人设特点等。默认人设（已写入 `workspace/agent_memory.md` 固定区，可改）：
    > 你是用户的专属学习/效率智能体。风格：严谨、直接、少废话，先做事再汇报。职责：基于个人知识库回答问题，联网补全时效信息，帮用户执行命令与处理文件。原则：引用来源；不确定就说不知道；写文件/执行命令遵守权限设置；只能在可变区记录学到的信息，不得改动本区。
  - **可变区（DYNAMIC）**：Agent 在工作过程中自行记录/更新的重要信息——本机重要目录、常用命令、用户偏好、项目背景等。"学到的重要东西"随时追加，下次对话自动带上。
- 提供"查看/清空可变区"入口；固定区由用户维护，模型只读写可变区。

**f) Revert 回退（会话 + 文件状态回退至指定轮前）**
- 每当 Agent 轮次涉及文件写改（`write_file`/`edit_file`）或命令执行，执行**前**先对该轮将影响的文件做快照（`conversations/{cid}/snapshots/{turn}/`）。
- 对话页每条 assistant 消息旁提供"↩ 回退到此"按钮；点击后：
  1. **文件状态回退**：恢复该轮及之后所有快照到执行前；
  2. **会话回退**：截断该轮及之后的消息，回到该轮之前的状态。
- 被回退的历史不销毁，移入"回收站"软保留，可再翻看（必要时人工恢复）。
- 说明：`write_file`/`edit_file` 的文件回退**完整可靠**；`run_command` 副作用属尽力回退（命令本身可能不可逆，故破坏性命令建议保持在批准制下执行）。

**g) 流式输出**
- 对话问答、工具结果展示均通过 SSE 流式推送（打字机效果），与任务进度共用同一通道。

**h) 长时任务**
- `run_command` 支持后台执行：超过阈值（默认 60s）的命令转入后台任务，Agent 可轮询/通知结果，不被前端超时打断。

**i) Agent LLM 配置**
- 页面内独立配置（base_url/key/model），要求模型支持 function calling；与总结 LLM 可以相同也可以不同。
- 模型不支持视觉 → 自动注册 `ocr_image` 工具并在系统提示中告知 Agent 用它看图。
- 模型不支持联网/工具时回退策略：系统提示明确告知可用工具集。

| 类别 | 要求 |
|------|------|

## 7. 技术选型建议

| 层 | 选型 | 理由 |
|----|------|------|
| 语言 | Python 3.10+ | 与现有代码一致 |
| Web | FastAPI + Jinja2 + SSE | 复用 temp 骨架 |
| 下载 | 抖音：移植现有；B 站：yt-dlp | 社区维护，抗反爬 |
| 音频 | ffmpeg | 已有代码 |
| ASR / LLM / 嵌入 / VLM | 均为 OpenAI 兼容接口，四组独立配置 | 供应商随时可换，默认硅基流动起步 |
| 向量库 | sqlite-vec（SQLite 扩展） | 零运维，与主库同文件生态；个人量级足够 |
| Agent 框架 | 自研可控 tool-call 循环（含联网/文件/命令工具 + 三级权限 + 快照回退 + 全局记忆注入） | 需求明确、要可控可回退，不引 LangChain 重依赖；工具集以注册表方式开放扩展 |
| 联网搜索 | Tavily（默认，用户已提供 key）/ Querit（备选） | 专为 LLM 优化的搜索 API，返回结构化结果，回答可标注来源 |
| OCR | 视觉 LLM API（默认）/ PaddleOCR（P2 本地） | 灵活、准确 |
| 文章抽取 | trafilatura | 正文抽取效果好 |

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 平台反爬升级 | 下载不可用 | 解析器模块化隔离；yt-dlp 跟随社区更新 |
| ASR 专业术语识别差 | 笔记质量下降 | 标题作 context；LLM 总结阶段纠错；ASR 可整体换供应商 |
| 长视频成本与耗时 | 体验差 | 16kHz 压缩、分段并发、B 站直下音频流 |
| 需登录内容 | 部分失败 | P2 支持配置 B 站 Cookie（SESSDATA） |
| **Agent 误操作** | 误删文件/危险命令/错误执行 | 三级权限（默认批准制 + 完全访问开关）；文件边界优先级 + 越界升级询问；命令黑名单永远兜底；**Revert 回退**可一键恢复文件与会话；审计日志全程留痕 |
| **RAG 答非所问** | 信任度下降 | 混合召回（向量+关键词）；强制引用来源；检索不到时明确说"库中没有"并建议联网补查 |
| **联网信息可信度（新增）** | 引入不实/过期信息 | 回答标注来源 URL；关键事实建议用户核实；可关闭联网仅走知识库 |
| 嵌入成本随库增长 | 成本上升 | 只嵌入总结+转录分块一次；重新总结才重嵌；用量统计可见 |
